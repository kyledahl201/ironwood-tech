## Step: teach
This week there's no API key and no magic. We're opening the hood. A **large language model** (LLM) does one thing, over and over: it looks at some text and predicts **what piece of text comes next**. Then it adds that piece and predicts again. A whole essay is thousands of those little predictions in a row.

Everything else, from chat to tool use to agents, is built on that loop. If you understand the loop, the strange things models do stop looking strange.

## Step: teach
The model doesn't read letters or words. It reads **tokens**: chunks of text, each turned into a number. A common word like `the` is usually one token. A rare word gets split into several pieces. Spaces and punctuation count too.

A rough rule for English: **one token is about 4 characters**, or about three-quarters of a word. You'll lean on that rule every time you estimate cost.

## Step: teach
Let's build a **toy tokenizer**, one that splits text into words and punctuation marks. Real tokenizers are smarter, but the idea is the same: text in, a list of pieces out.

Python's `re` module (regular expressions) is good at this. `re.findall(pattern, text)` returns every piece of the text that matches the pattern, as a list. In a pattern, `\w+` means "one or more letters, digits or underscores", and `|` means "or".

## Step: teach
Real tokenizers use **subword** pieces, learned from huge amounts of text. A made-up example: `unbelievable` might become `un` + `believ` + `able`. Common words stay whole, and rare words, names, numbers and code get chopped up.

That's why the same idea can cost different amounts depending on how it's written. In the lab, you'll build a small subword tokenizer yourself.

## Step: teach
Next, the **context window**. It's everything the model can see at once, measured in tokens: your instructions, the whole conversation so far, any documents you pasted in, **and the reply it's writing**. Models have a maximum. Go over it and something has to be cut.

The model has no memory between calls. Each call, you send the whole conversation again. That's why long chats get slower and more expensive, and it's why Week 5 is all about memory.

## Step: teach
At each step, the model doesn't output one answer. It outputs a **probability** for every possible next token. Here's a made-up example after the text "The crew will arrive on":

```
Monday   0.40
Tuesday  0.30
time     0.20
a        0.10
```

Then a token is **sampled** (picked) from those odds. Show me the trace, and you'd see these numbers at every single step.

## Step: teach
**Temperature** controls how adventurous the picking is.

- **Low temperature** (near 0): almost always pick the top token. It's predictable and repetitive. Good for extracting data, classifying and code.
- **High temperature** (1 and above): the odds get flattened, so unlikely tokens get picked more. It's more varied and more surprising, and also more likely to drift. Good for brainstorming.

Temperature doesn't make a model smarter or dumber. It changes how it chooses from what it already predicted.

## Step: teach
Now **cost**. Providers charge per token, usually quoted **per million tokens**, with two prices: **input** tokens (everything you send) and **output** tokens (everything it writes). Output is usually several times more expensive.

For practice we'll use **pretend prices**: $3 per million input tokens and $15 per million output tokens. Real prices change often, so always check the provider's pricing page before you budget a real project.

## Step: teach
Look at what you just computed: one call with a couple of pages of input cost about a penny. That sounds like nothing until an agent makes 30 calls per task, re-sending the growing conversation every time, for 1,000 users a day.

Two more things to remember. **Latency** (waiting time) grows with the number of output tokens, because the model writes them one at a time. That's why apps **stream** the reply as it's written. And shorter prompts are cheaper and faster, so every token you send should earn its place.

## Study guide
- An LLM predicts the next token, adds it to the text, and repeats.
- Tokens are chunks of text. A rough rule: 1 token ≈ 4 characters of English ≈ 3/4 of a word.
- Rare words, names, numbers and code split into more tokens.
- The context window is everything the model sees in one call, including its own reply. It has no memory between calls.
- The model outputs probabilities, and a token is sampled from them.
- Low temperature means predictable (extraction, code). High temperature means varied (brainstorming).
- Cost = input tokens × input price + output tokens × output price, priced per million. Output usually costs more.
- Latency grows with output length, which is why apps stream.

## Flashcards
- What does an LLM do at each step? :: Predicts probabilities for the next token, then one is picked.
- Rough characters per token in English? :: About 4.
- What's in the context window? :: The system prompt, the conversation, any documents, and the reply being written.
- Does a model remember the last call? :: No. You send the conversation again every time.
- Temperature 0 means? :: Always pick the most likely token (greedy).
- When do you want high temperature? :: Brainstorming and varied wording. Not extraction or code.
- Which usually costs more per token, input or output? :: Output.
- Why do chat apps stream replies? :: Output is written one token at a time, so streaming shows progress instead of making you wait.
