## Step: teach
Today is one of the most important lessons in the whole program, so we'll go slowly.

A **method** is a named, reusable piece of code. You give it values (called **arguments**), it does some work, and it hands a value back (its **return value**). Rails apps are mostly methods calling other methods.

We'll also settle something you flagged on placement day: `puts` does **not** mean return. They're different jobs, and mixing them up is the most common beginner bug there is.

## Step: teach
Here's a method:

```ruby
def double(n)
  n * 2
end
```

- `def` starts it and `end` closes it.
- `double` is its name. `n` is a **parameter**, a variable that holds whatever you pass in.
- Ruby automatically returns the value of the **last line**. Here, that's `n * 2`.

Calling it looks like `double(21)`, and its value is `42`.

## Step: teach
Notice the split you just made. **The method computed. The caller printed.** That's the pattern you'll use forever.

- `return` (or the last line) hands a value **back to the code that called the method**. The program can keep using it.
- `puts` shows text **on the screen** for a human. Then it's gone. The program can't use it.

## Step: teach
Methods can take more than one argument. Separate them with commas, both in the `def` line and in the call:

```ruby
def area(width, height)
  width * height
end

area(3, 4)   # => 12
```

The order matters. The first value goes into the first parameter.

## Step: teach
One more thing: the explicit `return` keyword. It returns a value immediately and skips the rest of the method:

```ruby
def double(n)
  return n * 2
end
```

Rubyists usually leave `return` off when it's the last line. You'll see it used to exit early, which we'll do once you know `if`.

## Step: quiz

def a(n)

- [x] `b`, because the program gets the value back and can keep using it

> `a(5)` returns nil. `b(5)` returns 10, which you can store, add to, or print whenever you like.

## Study guide
- `def name(params) ... end` defines a method. Call it with `name(args)`.
- The last line's value is returned automatically. `return` returns early and explicitly.
- `puts` prints for a human and returns `nil`. It does not hand anything back.
- Methods compute and return. The code that calls them decides whether to print.
- Multiple parameters are separated by commas, and the arguments fill them in order.
- If a value shows up as `nil` (or blank in a string), look for a `puts` that should be a return.

## Flashcards
- What does a Ruby method return if there's no `return`? :: The value of its last line.
- What does `puts` return? :: `nil`
- `x = puts "hi"`. What is x? :: `nil` (and "hi" was printed).
- What's a parameter? :: The variable in the `def` line that receives a value, like `n` in `def double(n)`.
- What's an argument? :: The actual value you pass in, like `21` in `double(21)`.
- Who should print, the method or the caller? :: The caller. Methods return values.
- What does `return` do in the middle of a method? :: Hands back the value immediately and skips the rest.
- `def a(n) puts n end`. What is `a(3) + 1`? :: An error: `a(3)` is `nil`, and you can't add to nil.
